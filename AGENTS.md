# Agent notes

Start with `uv run d1bench status --json`. It exits 1 and lists problems if the machine is not ready.

## Reading results

- Read `RESULTS.md`, or run `uv run d1bench report --json`.
- `RESULTS.md`, `results/comparison.json` and `results/correctness.json` are generated by `d1bench report`. Do not edit them by hand.
- d1 generates no tokens. Do not add decode, TTFT or generation-throughput metrics.

## Running benchmarks

- Use the `d1bench` CLI, not the runner modules directly. `uv run d1bench --help` lists commands.
- `uv run d1bench run <id> --json` overwrites that benchmark's files in `results/`, which are the published evidence. Rerun only when asked.
- Never run two benchmarks, or any other heavy work, at the same time.
- Results must not contain machine paths. Write JSON with `write_json` and pass log text through `redact` (both in `d1bench/common.py`).

## Changing code

1. Add or change a benchmark in `benchmarks.toml`. A new runner kind also needs an entry in `RUNNERS` in `d1bench/cli.py` and a branch in `summarize.py` and `evaluate.py`.
2. Before finishing, run `uv run ruff format d1bench`, `uv run ruff check d1bench`, `uv run mypy`, `uv run pylint d1bench` and `uv run pyscn check d1bench`. All must pass.
3. Commit messages follow Conventional Commits.

## Planning files

Plans live in `.planning/<date>-<slug>/` (planning-with-files layout). `.planning/2026-11-13-d1-2b-benchmark/` is the finished first session: a historical log, not current instructions.
